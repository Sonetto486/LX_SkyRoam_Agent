SkyRoam 智能旅游攻略生成系统
配置和使用说明（全项目）

更新时间：2026-05-19

====================================================
一、项目概览
====================================================
本项目为“智能旅游攻略生成系统”，核心包括：
1) 前端 Web（React + TypeScript）
2) 后端 API（FastAPI）
3) PostgreSQL + Redis
4) 异步任务（Celery Worker / Beat）
5) 高德 MCP HTTP 服务
6) 小红书 API 服务

主要场景：
- 智能导入（文本/链接/OCR）
- AI 助手 + RAG 检索增强
- 行程生成、编辑、保存
- 个人页面（收藏、高亮、旅行记录）


====================================================
二、环境要求
====================================================
1) Docker 部署（推荐）
- Docker Desktop 20.10+
- Docker Compose v2+

2) 本地开发部署
- Python 3.10+
- Node.js 18+
- PostgreSQL 15+
- Redis 7+

====================================================
四、配置说明（重点）
====================================================
【重要】
1) 请不要把真实密钥提交到 Git。
2) 如果 `env.example` 中出现看似真实密钥，请在你的本地配置中全部替换为你自己的值。

建议做法：
- 复制 `env.example` 生成你的环境文件。
- 本地开发推荐放在 `backend/.env`（因为后端常在 `backend` 目录启动，`config.py` 会读取 `.env`）。

建议至少配置以下变量：

1) 基础
- APP_NAME=SkyRoam
- DEBUG=true/false
- HOST=0.0.0.0
- PORT=8001（按你的启动脚本）

2) 数据库与缓存
- DATABASE_URL=postgresql://用户名:密码@localhost:5432/skyroam
- REDIS_URL=redis://localhost:6379/0

3) AI 能力
- OPENAI_API_KEY=你的Key
- OPENAI_API_BASE=你的服务地址（如 dashscope 兼容地址）
- OPENAI_MODEL=使用模型名

4) 地图与 OCR（强烈建议）
- AMAP_API_KEY=你的高德 Key（用于地理编码/地点搜索）
- BAIDU_OCR_API_KEY=你的百度 OCR Key
- BAIDU_OCR_SECRET_KEY=你的百度 OCR Secret

5) 前端（按需）
- REACT_APP_API_BASE_URL=http://localhost:8001/api/v1


====================================================
五、启动方式
====================================================
A. Docker 方式（推荐）
---------------------------------
1) 在项目根目录执行（Windows）：
	start.bat

2) 默认对外端口（来自 docker-compose.yml）：
- 前端： http://localhost:13000
- 后端： http://localhost:8001
- 高德 MCP： http://localhost:13002
- 小红书 API： http://localhost:18002
- PostgreSQL： localhost:5432

3) 常用命令（在根目录执行）：
	docker compose ps
	docker compose logs -f backend
	docker compose logs -f frontend
	docker compose down


B. 本地开发方式（Windows）
---------------------------------
方式1：快速开发（前后端）
1) 执行：start-dev.bat
2) 默认：
- 前端： http://localhost:3000
- 后端： http://localhost:8001
- API Docs： http://localhost:8001/docs

方式2：全服务开发（含 Celery/MCP/XHS）
1) 执行：start-all-win.bat
2) 会分别启动：Backend、Celery Worker、Amap API、XHS API、Frontend

====================================================
九、常见问题与排查
====================================================
1) 高德地点搜索失败：INVALID_USER_KEY
- 检查 `AMAP_API_KEY` 是否正确
- 检查高德控制台是否开通 Web 服务 API 权限
- 检查 Key 白名单限制（IP/域名）

2) POST /api/v1/smart-plan 返回 404
- 检查路由是否已在 `backend/app/api/v1/api.py` 注册

3) 前端请求失败/跨域问题
- 检查前端 `REACT_APP_API_BASE_URL`
- 检查后端实际端口（8001/8000）是否一致

4) 数据库连接失败
- 检查 `DATABASE_URL`
- 检查 PostgreSQL 服务是否可用

5) Redis/Celery 不工作
- 检查 Redis 是否启动
- 检查 `CELERY_BROKER_URL`、`CELERY_RESULT_BACKEND`

6) 智能导入解析为空
- 查看后端日志中 smart_import 解析输出
- 检查 AI Key、模型可用性、输入文本质量


====================================================
十、安全与规范建议
====================================================
1) 不要提交 `.env`、`.env.docker`、真实密钥到仓库
2) 在生产环境使用独立数据库与最小权限账号
3) 日志中避免打印完整密钥、Token
4) 部署前统一检查 API 地址与端口映射


====================================================
十一、建议的首次使用顺序
====================================================
1) 配置环境变量（先 AI、DB、Redis、AMAP）
2) 启动数据库与 Redis
3) 启动后端，再启动前端
4) 打开 API docs 验证接口健康
5) 执行一次智能导入和行程生成
6) 在个人页面验证收藏/旅行记录展示
